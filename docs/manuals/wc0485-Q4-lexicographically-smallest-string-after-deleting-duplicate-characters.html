Problem Essence

Given a string s of lowercase letters, you may repeatedly delete one copy of any letter that currently appears more than once. The operation preserves order and can be applied any number of times. Return the lexicographically smallest string reachable by any sequence of such deletions.

Every distinct letter in s must appear at least once in the result -- you can only delete a letter if a duplicate remains. Because duplicates provide "free" deletions, the optimal strategy picks characters greedily from left to right, always choosing the smallest letter whose selection still leaves every other required letter reachable later in the string.

Worked Example

Input: s = "aaccb"   Expected output: "aacb"

Precompute: distinct chars = {a, b, c}. Last occurrence indices: a->1, c->3, b->4.

Step-by-step trace:

Before each pick, compute limit = min(last_occurrence[c] for c in need). This is the rightmost index we may choose at while still guaranteeing every remaining needed char has at least one copy after our pick.

  • Step 1: need={a,b,c}. limit = min(last[a]=1, last[b]=4, last[c]=3) = 1. Scan a..z in [cur=0, limit=1]: 'a' at index 0 is in range. After picking it, suffix s[1:]="accb" covers {a,c,b} -- all remaining needed chars are reachable. Pick 'a'. need={b,c}, cur=1, result="a".
  • Step 2: need={b,c}. limit = min(last[b]=4, last[c]=3) = 3. Scan a..z in [cur=1, 3]: 'a' at index 1 is in range and suffix s[2:]="ccb" covers {c,b}. Pick 'a'. need={b,c} unchanged (a was already satisfied), cur=2, result="aa".
  • Step 3: need={b,c}. limit = min(4, 3) = 3. 'a' exhausted (last 'a' was at 1 < cur=2). 'b' at index 4 > limit=3, skip. 'c' at index 2 <= 3. After picking c(2), suffix s[3:]="cb" covers {b}. Pick 'c'. need={b}, cur=3, result="aac".
  • Step 4: need={b}. limit = last[b] = 4. 'b' at index 4 <= 4. After picking b(4), suffix s[5:]="" -- no more chars needed. Pick 'b'. need={}, result="aacb". Done.

Result: "aacb". Correct.

Decision Rule / Algorithm

Rule: Greedily build the result one character at a time. At each step, compute a deadline: limit = min over all still-needed chars c of last_occurrence(c). This is the latest index you may pick at without permanently losing some needed char. Within the window [cur, limit], pick the lexicographically smallest available character whose earliest occurrence in that window keeps all other needed chars reachable.

Preconditions:

  • Every distinct letter in the original string must appear exactly once in the final result at minimum (duplicates of already-satisfied letters may optionally appear again if they fit before the current limit).
  • A character c at position j is "feasible" iff suffix_mask[j+1] covers every still-needed char other than c.

Why the limit is tight: Suppose limit = last_occurrence(x) for some needed char x. If we pick a position j > limit, then j > last_occurrence(x), meaning x has no remaining occurrence after j and can never be added -- contradiction. Picking at or before limit guarantees x is still reachable.

Complexity: O(26 * n) time (at most 26 outer iterations, each scanning at most 26 letters and advancing a pointer over n positions total), O(26 * n) space for the optional next-occurrence table or O(n) space for the position-list variant.

Implementation Skeleton

class Solution:
    def lexSmallestAfterDeletion(self, s: str) -> str:
        n = len(s)
        pos = [[] for _ in range(26)]   # positions of each letter
        last = [-1] * 26                # last occurrence index
        for i, ch in enumerate(s):
            c = ord(ch) - 97
            pos[c].append(i)
            last[c] = i

        need = [last[c] >= 0 for c in range(26)]  # True if c must appear in result
        ptr  = [0] * 26   # next unconsumed position pointer per letter
        cur  = 0          # current scan start
        res  = []

        while any(need):
            # Deadline: picking past limit loses the most-constrained needed char
            limit = min(last[c] for c in range(26) if need[c])

            for c in range(26):
                # Advance pointer to first occurrence at or after cur
                while ptr[c] < len(pos[c]) and pos[c][ptr[c]] < cur:
                    ptr[c] += 1
                if ptr[c] >= len(pos[c]):
                    continue
                j = pos[c][ptr[c]]
                if j > limit:
                    continue  # no occurrence of c within deadline

                # Feasibility: all other needed chars must still appear after j
                ok = all(
                    not need[d] or last[d] > j
                    for d in range(26) if d != c
                )
                if ok:
                    res.append(chr(c + 97))
                    if need[c]:
                        need[c] = False   # c is satisfied
                    cur = j + 1
                    ptr[c] += 1
                    break

        return ''.join(res)
The inner feasibility check (last[d] > j) is equivalent to testing whether suffix_mask[j+1] covers all remaining needed letters -- both views appear in accepted solutions. The last[d] > j form avoids precomputing suffix bitmasks.

Reimplementation Checklist

  • Precompute the last occurrence index for every distinct letter in s.
  • Track a "need" set / bitmask of letters not yet placed in the result.
  • Before each pick, recompute limit = min(last[c] for c in need) -- this is your hard deadline.
  • Scan letters 'a' to 'z' in order; for each, find its earliest position at or after cur.
  • Accept the first letter whose earliest position is <= limit AND whose suffix covers all other still-needed letters (feasibility check).
  • After picking position j, set cur = j + 1 and remove the letter from need only if this was its last required inclusion.
  • Continue until need is empty; extra copies of already-satisfied letters can appear naturally because they pass the feasibility check too.
  • Edge case: if s has only one character or all characters are distinct, return s (the algorithm handles this correctly -- each letter is needed exactly once and no deletion is ever possible).

Wrong But Tempting

Approach 1: Apply "Remove Duplicate Letters" (LC 316) directly.
LC 316 builds the lexicographically smallest subsequence with exactly one copy of each letter. For "aaccb" that gives "acb", but the correct answer is "aacb". The difference: here we may keep multiple copies of a letter when doing so produces a lexicographically smaller prefix. The constraint is only that we cannot reduce any letter below 1 copy, not that we must reduce it to exactly 1. Complexity of the wrong approach: O(n) time, but systematically produces Wrong Answer whenever an extra copy of a small letter appears before a needed larger letter.
Approach 2: Greedy scan for globally smallest char with no limit constraint.
At each step, scan s[cur:] for the smallest character and pick its first occurrence. This ignores the deadline: for "bac", need={a,b,c}; picking 'a' at index 1 sets cur=2, but 'b' only exists at index 0 < cur -- it can never be placed. Result: wrong or infinite loop. Complexity: O(n) per step, O(26) steps = O(26n) ~ O(n). Fast but wrong; 14+ Wrong Answer verdicts in this benchmark confirm the feasibility check is mandatory.
Approach 3: O(n^2) naive feasibility check per candidate position.
At each of the at most n picks, for each candidate position j scan s[j:] (O(n)) to verify every needed char is still present. Total: O(n) candidates * O(n) scan = O(n^2). For n = 10^5: 10^5 * 10^5 = 10^10 ops -- TLE. The fix is to precompute either suffix_mask[i] (bitmask, O(26n) space) or last[c] (O(26) space) so each feasibility check is O(26) rather than O(n).

Family B -- Greedy + suffix bitmask + next-occurrence table

            pos = j + 1
            need &^= (1 << c)
            break
        }
    }

Family C -- Monotonic Stack

Files: accepted__glm-5-cloud-t0.8-javascript__javascript.js.

Maintains a monotonic stack similar to "Remove Duplicate Letters" (LC 316), but tracks inStack[c] (copies of c currently on stack) and count[c] (remaining copies not yet processed). A larger top is popped only if it has duplicates either remaining in count or extra copies already on the stack. A post-processing pass removes trailing duplicates. This is the most concise approach but the hardest to reason about for correctness.

Excerpt (from accepted__glm-5-cloud-t0.8-javascript__javascript.js):

for (const c of s) {
    const idx = c.charCodeAt(0) - 'a'.charCodeAt(0);
    while (stack.length > 0) {
        const topIdx = stack[stack.length-1].charCodeAt(0) - 'a'.charCodeAt(0);
        if (topIdx <= idx) break;
        if (count[topIdx] > 0 || inStack[topIdx] > 1) {
            stack.pop(); inStack[topIdx]--;
        } else { break; }
    }
    stack.push(c); inStack[idx]++; count[idx]--;
}
while (stack.length > 0) {
    const lastIdx = stack[stack.length-1].charCodeAt(0) - 'a'.charCodeAt(0);
    if (inStack[lastIdx] > 1) { stack.pop(); inStack[lastIdx]--; }
    else break;
}
Family D -- Sliding Window Minimum Deque

Files: accepted__claude-sonnet-4-6__python3.py.

Maintains a monotonic deque of indices representing a sliding-window minimum over s. The deque is expanded lazily up to the current min_last deadline and its front (after discarding consumed positions) gives the leftmost minimum in [prev_pos+1, min_last]. Elegant O(n) amortized expansion, but functionally equivalent to Family A/B.

Excerpt (from accepted__claude-sonnet-4-6__python3.py, main loop):

while unsatisfied:
    min_last = min(last_occ[c] for c in unsatisfied)
    while window_right < min_last:
        window_right += 1
        while dq and s[dq[-1]] > s[window_right]:
            dq.pop()
        dq.append(window_right)
    while dq[0] <= prev_pos:
        dq.popleft()
    p = dq[0]
    result.append(s[p])
    unsatisfied.discard(s[p])
    prev_pos = p

Failure Patterns From Stats

StatusCountLikely root cause (inferred from accepted invariants)
Wrong Answer 13
  • Missing feasibility check -- picking the smallest char greedily without verifying every other needed char still appears in the suffix.
  • No limit / deadline computation -- picking past the last occurrence of a needed char, making it impossible to include later.
  • Off-by-one in limit: using limit = min(last[c]) - 1 or pos < limit instead of pos <= limit, causing valid positions to be skipped.
  • Treating the problem as strict deduplication (keep exactly one of each) rather than allowing extra copies of already-satisfied letters.
  • Applying LC 316 "Remove Duplicate Letters" directly -- correct structure but wrong invariant (produces "acb" for "aaccb" instead of "aacb").
Runtime Error 1 Likely an index-out-of-bounds when advancing a pointer past the end of a position list, or an infinite loop that times out -- e.g., failing to advance ptr[c] after picking a position, so the same index is reconsidered and the need set never empties.
