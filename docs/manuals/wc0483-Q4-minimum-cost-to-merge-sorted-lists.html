Problem Essence

Given n ≤ 12 non-empty sorted lists, you may repeatedly pick any two lists a and b, pay cost len(a) + len(b) + |median(a) − median(b)|, and replace them with their merged sorted list. The median is defined as the left-middle element (index (len−1)//2). Find the merge order that minimises the total cost to reduce all lists to one.

Because any two lists can be merged at any step (not just adjacent ones), and the optimal split at each level is non-obvious, the problem requires searching over all 2n subset partitions — a classic bitmask DP setup. The small bound n ≤ 12 (giving 4096 masks and 531 441 submask transitions via the 3n identity) makes this tractable.

Decision Rule / Algorithm

Precondition: n ≤ 12 (so 2n = 4096 masks and 3n = 531 441 submask transitions fit in milliseconds). Total elements ≤ 2000.

Core recurrence:

dp[mask] = 0                                    if popcount(mask) == 1
dp[mask] = min over all proper splits (sub, comp=mask^sub) of:
               dp[sub] + dp[comp] + size[mask] + |median[sub] − median[comp]|

Key simplification: Because size[sub] + size[comp] = size[mask] for any split, the length cost is constant per mask — only the median term varies with the split choice. This means we need to find the split that minimises dp[sub] + dp[comp] + |median[sub] − median[comp]|.

Submask enumeration trick: All proper non-empty submasks of mask can be iterated with sub = (mask-1) & mask; while sub: sub = (sub-1) & mask. This visits each submask exactly once. The total number of (mask, sub) pairs over all masks equals 3n by the identity ∑_{k=0}^{n} C(n,k)·2k = 3n; for n=12 this is 531 441, confirming tractability.

Answer: dp[(1<<n) − 1] — the full mask containing all lists.

Each larger mask can be formed from multiple (sub, comp) splits; the DP picks the minimum-cost one.

Implementation Skeleton

Python 3 — incremental merge via lowest-set-bit trick (avoids re-sorting):

from typing import List

class Solution:
    def minMergeCost(self, lists: List[List[int]]) -> int:
        n = len(lists)
        full = (1 << n) - 1

        # Build merged sorted array for every mask via the lowest-bit trick.
        # merged[mask ^ lsb] is already computed when we process mask.
        merged = [[] for _ in range(1 << n)]
        size   = [0] * (1 << n)
        med    = [0] * (1 << n)

        for mask in range(1, 1 << n):
            lsb  = mask & -mask                      # isolate one set bit
            i    = lsb.bit_length() - 1              # its list index
            prev = mask ^ lsb                        # mask without that list
            a, b = merged[prev], lists[i]
            c, p, q = [], 0, 0
            while p < len(a) and q < len(b):
                if a[p] <= b[q]: c.append(a[p]); p += 1
                else:            c.append(b[q]); q += 1
            c.extend(a[p:]); c.extend(b[q:])
            merged[mask] = c
            size[mask]   = len(c)
            med[mask]    = c[(len(c) - 1) // 2]     # left-middle for even length

        dp = [float('inf')] * (1 << n)
        for i in range(n):
            dp[1 << i] = 0                           # single list: zero merge cost

        for mask in range(1, 1 << n):
            if mask & (mask - 1) == 0:               # skip singletons
                continue
            sub = (mask - 1) & mask                  # start submask iteration
            while sub > 0:
                comp = mask ^ sub
                if sub < comp:                       # count each unordered split once
                    cost = (dp[sub] + dp[comp]
                            + size[mask]             # size[sub]+size[comp] == size[mask]
                            + abs(med[sub] - med[comp]))
                    if cost < dp[mask]:
                        dp[mask] = cost
                sub = (sub - 1) & mask

        return dp[full]

Complexity: Precomputation O(2n·N) where N=total elements ≤ 2000. DP transitions O(3n). For n=12: ~8M merge ops + 531K DP steps.

Reimplementation Checklist

  • Initialise dp[1<<i] = 0 for every singleton mask i — a single list needs no merging.
  • Precompute size[mask] using size[mask ^ lsb] + len(lists[i]) (lowest-bit trick avoids iterating all set bits).
  • Precompute med[mask] at index (size[mask] − 1) // 2 — left-middle for even-length arrays per the problem definition.
  • Enumerate all proper non-empty submasks of mask with sub = (mask−1) & mask; while sub: sub = (sub−1) & mask.
  • Avoid double-counting each unordered split by processing only when sub < comp (or equivalently sub < mask ^ sub).
  • Use the constant-size shortcut: size[sub] + size[comp] = size[mask], so the length term is the same for every split of the same mask.
  • Use 64-bit integers in C++/Java/Go/Rust — values up to 109, lengths up to 2000, up to 11 merge levels: max cost ≈ 11·2000 + 11·2·109 requires >32 bits.
  • Return dp[(1<<n) − 1] — the full mask.

Wrong But Tempting

1. Greedy — always merge the cheapest available pair

Complexity: O(n2) merges, each O(N log N) → O(n2·N·log N) = 144·2000·11 ≈ 3.2M ops — fast enough.

Why it fails: Merging cheaply now can poison future medians. Example: lists [1],[2],[1000]. Greedy picks [1]+[2] (cost=3), leaving {[1,2],[1000]}; final cost 3+(2+1+998)=1004. But merging [2]+[1000] first (cost=1000), then [1]+[2,1000] (cost=1+2+|1−500|=502), total=1502 — greedy wins here but fails on carefully constructed inputs where the cheapest early merge shifts a median adversely. The median effect is non-linear and cannot be evaluated without trying all splits.

2. Interval / contiguous-segment DP — dp[i][j] = min cost to merge lists[i..j]

Complexity: O(n3) states and transitions = 123 = 1728 — trivially fast.

Why it fails: This only explores merges of contiguous sub-arrays. The optimal strategy can merge non-adjacent lists first (e.g., L0 and L2 before L1), which an interval DP cannot express. Only a bitmask DP over arbitrary subsets is correct.

3. Bitmask DP but recomputing the median during each transition (no precomputation)

Complexity: Each of the 3n=531 441 transitions would need to find the median of the sub and comp masks by iterating over all elements — O(N) each → 531 441·2000 ≈ 1.06 × 109 operations → TLE (the 2 TLE submissions in this benchmark likely fell into this trap).

Fix: Precompute med[mask] for all 2n masks before the DP; transitions then use O(1) lookups.

Accepted Algorithm Families

Family A — Sort-on-Demand

For each mask, collect all elements from the constituent lists and sort. Store size[] and med[]. Simple; O(2n·N log N) precomputation; low memory.

Family B — Incremental Merge

Build merged[mask] by merging merged[mask^lsb] with lists[i] via two-pointer. Reuses prior work; O(2n·N) but stores 2n arrays → higher memory.

Family C — Binary Search (Coord. Compressed)

Precompute cnt[i][v] = # elements ≤ compressed-value v in list i. Binary search on compressed values to find the k-th element for each mask. No merged arrays stored.

Family D — Binary Search (Value Range)

Binary search on the raw integer range [−109, 109] to find the k-th element across all lists in the mask, using sort.Search / bisect_right per list. Clean; O(2n·n·log(2×109)) precomputation.
