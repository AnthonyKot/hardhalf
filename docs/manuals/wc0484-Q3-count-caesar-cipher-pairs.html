Problem Essence

You are given n strings, each of the same length m. Two strings are similar if one can be turned into the other by repeatedly shifting every character forward by one (cyclically, 'z' wraps to 'a')—in other words, if they are Caesar-cipher rotations of each other.

Count the number of ordered pairs (i, j) with i < j where words[i] and words[j] are similar.

The key insight is that two strings are similar if and only if they share the same relative character structure—the pattern of inter-character gaps mod 26 is shift-invariant, so it uniquely identifies a Caesar equivalence class.

The constraint n × m ≤ 105 means the total character count is small regardless of the individual values of n and m, so an O(n × m) solution processes everything in one linear pass.

Decision Rule / Algorithm

Invariant: Two strings s and t are Caesar-similar iff there exists an integer k such that t[i] = (s[i] + k) mod 26 for all i. Subtracting s[0] from every character of s (mod 26) yields a canonical key in which the first character is always 'a'. Two words are similar iff their canonical keys are identical.

Algorithm:

  1. For each word, compute its canonical key: key[i] = (ord(word[i]) − ord(word[0])) mod 26, encoded as characters 'a'–'z'.
  2. Maintain a frequency map freq[key] = count. For each new word, before inserting, add freq[key] to the answer (each existing word with the same key pairs with this one).
  3. Return the accumulated answer.

Correctness proof sketch: Any two similar strings s, t with common shift k have t[i] − t[0] = (s[i] + k) − (s[0] + k) = s[i] − s[0] (all mod 26), so their canonical keys are equal. Conversely, equal keys imply s[i] − s[0] = t[i] − t[0] mod 26, so t is a shift of s by t[0] − s[0].

Complexity: O(n × m) time and O(n × m) space. Given n × m ≤ 105, this is at most 105 character operations total — extremely fast in all languages.

Equivalent alternative: Instead of normalizing relative to the first character, one may store the sequence of consecutive differences (word[i+1] − word[i]) mod 26 for i = 0 … m−2. This is an equally valid invariant (the differences are shift-independent), producing a key of length m−1. Both approaches are used by accepted solutions.

Counting pairs shortcut: If a canonical key appears c times, it contributes c × (c−1) / 2 pairs. The incremental approach (adding freq[key] before incrementing) avoids a separate loop over the map and is simpler to implement correctly.

Implementation Skeleton

Python 3 
from typing import List
from collections import defaultdict

class Solution:
    def countPairs(self, words: List[str]) -> int:
        def canonical(word: str) -> tuple:
            # Shift every char so the first char maps to 'a' (position 0).
            offset = ord(word[0]) - ord('a')
            return tuple((ord(c) - ord('a') - offset) % 26 for c in word)

        freq: dict = defaultdict(int)
        answer = 0
        for word in words:
            key = canonical(word)
            # Every previously seen word with the same key pairs with this one.
            answer += freq[key]
            freq[key] += 1
        return answer

Uses an incremental frequency map: no second pass needed. The tuple key is hashable in Python. For C++/Go/Rust, encode key as a string/byte slice instead.

Reimplementation Checklist

  • Compute canonical key by subtracting word[0]'s offset (not word[0]'s absolute ordinal) from every character's ordinal, then take mod 26.
  • Apply + 26 before mod 26 when the difference might be negative (e.g., (a - z) mod 26 in languages without Python-style modulo).
  • Use a hashable representation for the key: tuple in Python, string in Go/Java/C++, Vec<u8> in Rust — not a raw array reference.
  • Count incrementally: add freq[key] to the answer before incrementing freq[key], so you do not double-count or need a second pass.
  • Return type must be long long / int64 / i64 — with n up to 105, the maximum pair count is ~5 × 109, which overflows a 32-bit integer.
  • Handle the edge case of single-character words: their canonical key is always (0,) (or the empty string for the consecutive-differences variant), so they all group together correctly without special-casing.
  • Verify with sample 2: ["ab","aa","za","aa"] should yield 2. Confirm "za" and "ab" share the same key, and the two "aa" entries share a key.

Wrong But Tempting

1. O(n²) brute-force pair comparison

For every pair (i, j), try all 26 shifts of words[i] and check equality with words[j]. Complexity: O(n² × 26 × m). With n = 105 (which is possible when m = 1), this gives (105)² × 26 = 2.6 × 1011 operations — orders of magnitude too slow. The n×m constraint does not protect the n² factor.

2. Grouping words by their first character

Count pairs only among words starting with the same letter, reasoning that a Caesar shift preserves the first character. This is incorrect: applying a non-zero shift changes the first character. For example, "fusion" (starts with 'f') and "layout" (starts with 'l') are similar via shift 6, but are in different groups. This approach would give 0 pairs for the first sample instead of 1.

3. Consecutive differences without mod 26

Store signed differences (word[i+1] − word[i]) as the key. This fails on wrap-around pairs. For instance, "za" has signed difference a − z = −25, while "ab" has difference b − a = +1. Without mod 26, −25 ≠ 1, so the pair is missed — but (−25 + 26) mod 26 = 1 reveals they are in the same class. Sample 2 would return 1 instead of 2.

Accepted Algorithm Families

Family A — Normalize-to-first (full-string key, length m)

Subtract word[0]'s offset from every character so the first character maps to 'a'. Encode the result as a string or tuple of length m. The resulting key is shift-invariant and uniquely identifies the equivalence class.

Members: claude-sonnet-4-6 (py), kimi-k2.5-t0.0 (py), glm-5-cloud (py), glm-5-t0.0 (py), qwen3.5-cloud (py, both temps), all 7 Java solutions, kimi-k2.5-golang, qwen3.5-golang, minimax-t1.0-golang, kimi-ts.

Illustrative excerpt from accepted__codex-agent-gpt-5.5-java__java.java:

// Java – normalize all chars so first maps to 'a', then hash the string
private String normalize(String word) {
    char[] key = new char[word.length()];
    int base = word.charAt(0) - 'a';
    for (int i = 0; i < word.length(); i++) {
        int shifted = (word.charAt(i) - 'a' - base + 26) % 26;
        key[i] = (char) ('a' + shifted);
    }
    return new String(key);
}

Family B — Consecutive differences (key of length m−1)

Compute (word[i+1] − word[i]) mod 26 for each adjacent pair. This sequence is invariant under any uniform Caesar shift because the shift cancels out in subtraction. The key has length m−1 (length-1 words all get the empty key, grouping them correctly).

Members: minimax-m2.7-cloud (py), deepseek-v4-pro-t1.0 (py), kimi-k2.5-javascript, deepseek-flash-javascript, deepseek-pro-javascript, minimax-t0.0-golang, kimi-rust.

Family C — Brute-force canonical (try all 26 shifts, pick lex-min)

For each word, generate all 26 Caesar rotations and take the lexicographically smallest as the canonical key. Correct, but costs O(26 × m) per word instead of O(m). In practice this is 26× slower and causes a runtime outlier.

Members: glm-5-cloud-t0.8 (JavaScript only).

Illustrative excerpt from accepted__glm-5-cloud-t0.8-javascript__javascript.js:

// JavaScript – try all 26 shifts, keep lex-minimum (OUTLIER: 9.8× slower)
function canonicalForm(s) {
    let minStr = s;
    for (let shift = 1; shift < 26; shift++) {
        let shifted = '';
        for (let i = 0; i < s.length; i++) {
            let code = (s.charCodeAt(i) - 97 + shift) % 26;
            shifted += String.fromCharCode(code + 97);
        }
        if (shifted < minStr) minStr = shifted;
    }
    return minStr;
}
