Problem Essence

You are given an undirected tree on n nodes (4 <= n <= 100000) and three distinct target nodes x, y, z. For every node u, compute the three hop-count distances dx, dy, dz to the targets. Node u is "special" when those three distances, sorted ascending as (a, b, c), satisfy a*a + b*b == c*c (a Pythagorean triplet).

The degenerate case (0, k, k) is valid -- any target node itself may be special if the other two targets are equidistant from it. Distances can reach n-1 = 99999, so a*a + b*b can reach about 2e10, which requires 64-bit integers in compiled languages.

Decision Rule / Algorithm

Rule: Run BFS three times -- once from each of x, y, z -- to produce distance arrays dx[0..n-1], dy[0..n-1], dz[0..n-1]. For each node u, sort its three distances into (a <= b <= c) and count u if a*a + b*b == c*c.

Precondition -- 64-bit arithmetic required: Maximum distance on a path graph with n=100000 is n-1=99999. Then a*a + b*b reaches at most 2 * 99999^2 = 19999600002, which exceeds the int32 maximum of about 2.1e9. In C++, Go, Java, and Rust you must cast to long / int64 before squaring; Python integers are unbounded by default.

Why three BFS runs suffice: Trees have unique paths, so BFS from a single source visits every node exactly once in O(n) time. Three independent BFS runs give exact hop-count distances for all n nodes to all three targets in O(n) total. There is no need for LCA, all-pairs shortest paths, or any path-compression technique.

Degenerate triplet (0, k, k): When u is one of the targets, its distance to itself is 0. The triplet (0, k, k) satisfies 0^2 + k^2 = k^2 for any k >= 0. So target nodes are always candidates and must not be excluded.

Implementation Skeleton

Python 3 -- canonical BFS-3x + sort approach. Matches the accepted accepted__claude-sonnet-4-6__python3.py.

from collections import deque
from typing import List

class Solution:
    def specialNodes(self, n: int, edges: List[List[int]], x: int, y: int, z: int) -> int:
        adj = [[] for _ in range(n)]
        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)

        def bfs(src: int) -> list:
            dist = [-1] * n
            dist[src] = 0
            q = deque([src])
            while q:
                node = q.popleft()
                for nb in adj[node]:
                    if dist[nb] == -1:
                        dist[nb] = dist[node] + 1
                        q.append(nb)
            return dist

        dx = bfs(x)
        dy = bfs(y)
        dz = bfs(z)

        count = 0
        for u in range(n):
            a, b, c = sorted([dx[u], dy[u], dz[u]])
            if a * a + b * b == c * c:
                count += 1
        return count

Time: O(n). Space: O(n) for adjacency list and three distance arrays. No sorting library beyond the three-element tuple is used; three-element sort is O(1).

Reimplementation Checklist

  • Build an undirected adjacency list -- add both directions for every edge.
  • Run BFS exactly 3 times: once from x, once from y, once from z. Each run must initialize all distances to -1 (or INF) and reset the queue.
  • Use int64 / long for squaring: cast distances before multiplying in C++, Java, Go, and Rust.
  • Sort the three distances per node (or use 3 manual comparisons) before applying the Pythagorean check.
  • Include the degenerate (0, k, k) case -- do NOT add a guard like if a > 0.
  • Return an int count, not a list of node indices.
  • Verify n >= 4 (guaranteed by constraints) so no empty-graph edge case is needed.

Wrong But Tempting

Approach 1: All-pairs BFS (O(n^2))

Run BFS from every node to find distances to x, y, z. Complexity: n * O(n) = O(n^2). For n = 1e5: 1e5 * 1e5 = 1e10 operations. Hard TLE. The fix is obvious once you notice that the three target distances can be gathered with exactly 3 BFS runs instead of n.

Approach 2: Recursive DFS for distances (stack overflow)

A recursive DFS to fill distances works on small inputs but fails on worst-case inputs. A path graph with n = 1e5 creates a recursion depth of 1e5. Python's default recursion limit is 1000; even with sys.setrecursionlimit the C stack overflows. Use iterative BFS (deque) or an explicit stack-based DFS.

Approach 3: Integer overflow with int32 arithmetic

Using plain int in Java or int in C++ for the Pythagorean check. Max distance = n-1 = 99999. Then a^2 + b^2 <= 2 * 99999^2 = 19999600002, which exceeds int32 max (2147483647 ~ 2.1e9) by roughly 9x. The result silently wraps or saturates, producing wrong answers only on large inputs where the test infrastructure has long chains. The fix: cast to long/int64 before multiplying.

Family 1 -- BFS-3x + library sort (10 Python, 5 JS/TS, 4 Java variants)

Build adjacency list, run BFS from each target, then for each node call the language's built-in sort on the three-element distance tuple and check the Pythagorean condition. This is the dominant pattern across all languages except C++ and the Rust/minimax-Go variants.

Family 2 -- BFS-3x + 3-swap manual sort (C++, Go kimi/qwen, TypeScript)

Same BFS structure, but the sort is replaced by three explicit conditional swaps -- a sorting network for three elements. Avoids any allocation from calling a sort function and lets the compiler inline the comparisons. Used in the C++ and most Go solutions.

Excerpt from: accepted__kimi-k2.5-cloud-t0.0-cpp__cpp.cpp (lines 22-33)

        int count = 0;
        for (int i = 0; i < n; ++i) {
            long long a = distX[i];
            long long b = distY[i];
            long long c = distZ[i];
            if (a > b) swap(a, b);
            if (b > c) swap(b, c);
            if (a > b) swap(a, b);
            if (a * a + b * b == c * c) {
                ++count;
            }
        }
        return count;

Family 3 -- BFS-3x + min/max arithmetic (Rust, minimax Go)

Instead of sorting, compute a = min(dx,dy,dz), c = max(dx,dy,dz), b = dx+dy+dz - a - c. This avoids the three-comparison network and reads as more declarative code, but is semantically identical.

Excerpt from: accepted__kimi-k2.5-cloud-t0.0-rust__rust.rs (lines 40-54)

            let a = dx.min(dy).min(dz);
            let c = dx.max(dy).max(dz);
            let b = dx + dy + dz - a - c;

            if a * a + b * b == c * c {
                count += 1;
            }

Family 4 -- Linked-array adjacency + DFS stack traversal (codex Java)

Uses three parallel arrays (head[], to[], next[]) to represent the adjacency list as a linked structure, then traverses with an explicit stack rather than a BFS queue. This avoids LinkedList allocation overhead and achieves the fastest Java runtime (36 ms vs median ~130 ms). The algorithm is still O(n) and finds the same distances as BFS; DFS on a tree gives correct hop-count distances when tracking parent to avoid revisiting.

Failure StatusLikely Root Cause (inferred)
Wrong Answer Integer overflow: using int32 for squared distances. Max a^2+b^2 ~ 2e10 >> int32 max (~2.1e9). All accepted C++/Java/Go/Rust solutions explicitly cast to 64-bit before squaring; omitting that cast produces silent wrong answers on long-chain inputs.
Wrong Answer Directed adjacency list: adding only one direction per edge. BFS from x fails to reach nodes on the other side of edges stored only in one direction, giving dist=-1 for unreachable nodes, causing bogus triplet checks.
Wrong Answer Excluding degenerate triplets: adding a guard if a > 0 before the check. Nodes x, y, z themselves may form valid (0, k, k) triplets and must be counted.

Time Limit Exceeded Running BFS from every node (O(n^2)): for n=1e5, this is 1e10 operations. Only 3 BFS runs are needed.
