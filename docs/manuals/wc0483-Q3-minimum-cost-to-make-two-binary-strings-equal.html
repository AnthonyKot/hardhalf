Problem Essence

Given two binary strings s and t of equal length, you must make them equal using three cost-bearing operations: flip any single bit in either string (cost flipCost), swap two positions within the same string (cost swapCost), or swap s[i] with t[i] at the same index across strings (cost crossCost).

Only positions where s[i] ≠ t[i] matter: positions where the strings already agree need no work. Each differing position is either a Type A mismatch (s='0', t='1') or a Type B mismatch (s='1', t='0'); the key insight is that a within-string swap can simultaneously fix one Type A and one Type B position, while two same-type mismatches require an additional cross-swap to create an opposite pair first.

The problem reduces entirely to counting how many Type A and Type B mismatches exist, then greedily choosing the cheapest repair strategy for each category of pair, with no need to track which specific positions are involved.

Worked Example

Input: s = "01000", t = "10111", flipCost = 10, swapCost = 2, crossCost = 2  →  Output: 16

Step 1 — Classify every position

Indexs[i]t[i]RelationType
001differA (s=0, t=1)
110differB (s=1, t=0)
201differA
301differA
401differA

Counts: a = 4 (Type A), b = 1 (Type B).

Step 2 — Pair opposite-type mismatches

paired = min(4, 1) = 1. Cost per pair = min(swapCost, 2·flipCost) = min(2, 20) = 2. Subtotal: 1 × 2 = 2.

Step 3 — Handle remaining same-type mismatches

remaining = |4 − 1| = 3. We pair them in groups of two. Cost per pair of two = min(crossCost + swapCost, 2·flipCost) = min(2+2, 20) = 4. Full pairs: ⌊3/2⌋ = 1. Subtotal: 1 × 4 = 4.

Step 4 — Lone leftover

remaining % 2 = 1, so pay flipCost = 10 once. Subtotal: 10.

Total: 2 + 4 + 10 = 16 ✓

Decision Rule / Algorithm

Precondition: n = len(s) = len(t), all costs are positive integers, 1 ≤ n ≤ 10⁵.

Step 1 — Count mismatches by type.
a = number of positions where s[i]='0', t[i]='1' (Type A).
b = number of positions where s[i]='1', t[i]='0' (Type B).

Step 2 — Fix opposite-type pairs.
paired = min(a, b). A Type A and Type B at different indices can be simultaneously fixed by one within-string swap at cost swapCost, or by flipping both bits for cost 2·flipCost. Choose the cheaper:
cost += paired × min(swapCost, 2·flipCost)

Step 3 — Fix same-type pairs.
r = |a − b| mismatches of a single type remain. Two same-type mismatches can be fixed by: (i) cross-swapping one to create an opposite pair, then applying a within-string swap — cost crossCost + swapCost; or (ii) flipping both — cost 2·flipCost:
cost += (r ÷ 2) × min(crossCost + swapCost, 2·flipCost)

Step 4 — Lone leftover.
If r is odd, one isolated mismatch remains. The only option is to flip it:
cost += (r % 2) × flipCost

Why Step 2 before Step 3? The cost per opposite pair is min(swap, 2·flip). The cost per same-type pair is min(cross+swap, 2·flip). Since crossCost ≥ 1 > 0, we have cross+swap ≥ swap, and also 2·flip ≥ 2·flip, so min(cross+swap, 2·flip) ≥ min(swap, 2·flip). Opposite pairs are always at least as cheap to fix, so exhausting them first is globally optimal.

Complexity: O(n) time (one pass to count), O(1) extra space. Final arithmetic is a handful of multiplications and comparisons on the three counts.

Implementation Skeleton

Python 3 — uses the verbatim signature from stats.json:

class Solution:
    def minimumCost(self, s: str, t: str, flipCost: int, swapCost: int, crossCost: int) -> int:
        # Count the two mismatch types in a single pass
        a = 0  # s[i]='0', t[i]='1'
        b = 0  # s[i]='1', t[i]='0'
        for si, ti in zip(s, t):
            if si != ti:
                if si == '0':
                    a += 1
                else:
                    b += 1

        # Step 2: fix min(a,b) opposite-type pairs
        paired = min(a, b)
        cost = paired * min(swapCost, 2 * flipCost)

        # Step 3: fix same-type pairs in groups of two
        r = abs(a - b)
        cost += (r // 2) * min(crossCost + swapCost, 2 * flipCost)

        # Step 4: lone leftover (r is odd)
        if r % 2 == 1:
            cost += flipCost

        return cost

Note: All intermediate values fit in Python's arbitrary-precision integers, but in statically typed languages use long / int64 — costs can reach 10⁹ × 10⁵ = 10¹⁴.

Reimplementation Checklist

  • Count a (Type A: s='0', t='1') and b (Type B: s='1', t='0') in a single O(n) pass; skip positions where s[i] == t[i].
  • Compute paired = min(a, b) and add paired × min(swapCost, 2·flipCost) to the answer.
  • Compute r = |a - b| (same-type excess); add (r ÷ 2) × min(crossCost + swapCost, 2·flipCost).
  • If r is odd, add exactly flipCost once for the lone remainder.
  • Use 64-bit integer arithmetic in Java, C++, Go, and Rust — the answer can exceed 2³¹ (up to ~10¹⁴); in Java cast costs to long before multiplication.
  • Return 0 immediately if both strings are already equal (a=0, b=0); no special-casing is needed since the formula evaluates to 0 automatically.
  • Verify against all three official examples: Example 2 exercises the path where swapCost ≫ flipCost (no swaps used), Example 3 is the zero-cost baseline.

Wrong But Tempting

1. Flip every mismatch individually

Cost = (a + b) × flipCost. This is an O(n) upper bound but ignores paired operations entirely. When swapCost = 1 and flipCost = 100 with a = b = 50000, the naive cost is 10⁷ while the correct answer is 50000 × 1 = 50000 — 200× too expensive. The formula happens to be correct only when swapCost ≥ 2·flipCost and crossCost + swapCost ≥ 2·flipCost simultaneously.

2. DP over positions tracking a running imbalance

A natural DP state might be (position i, net imbalance a−b seen so far), trying to decide at each step which operation to apply. This creates O(n) positions × O(n) imbalance values = O(n²) = 10¹⁰ states for n = 10⁵ — far too slow. The key reduction is that the specific positions of each mismatch type are interchangeable (any Type A can pair with any Type B), so only the global counts a and b matter, collapsing the entire problem to four arithmetic operations on two integers.

3. Always use cross+swap to fix same-type pairs, never flip

A solver might see that a cross swap converts Type A → Type B, enabling an opposite-pair swap, and use this unconditionally for all same-type pairs. When crossCost = 10⁹, swapCost = 10⁹, flipCost = 1, this approach pays 2 × 10⁹ per pair of same-type mismatches, while the correct answer is 2·flipCost = 2 — off by a factor of 10⁹. The fix is the single min(crossCost + swapCost, 2·flipCost) comparison. Arithmetic: n = 10⁵ same-type pairs × 2×10⁹ each = 2×10¹⁴, vs correct 10⁵ × 2 = 2×10⁵.

Family 3 — Candidate Enumeration  (2 solutions)
Python JavaScript

Models the problem as: how many cross-swaps k should we apply? Then evaluates cost as a function of k over a small candidate set rather than deriving the closed-form optimum analytically. Correct but circuitous — arrives at the same answer via a minimax over {0, −a, b, ⌊−d/2⌋, ⌊−d/2⌋+1}.

Excerpt from accepted__deepseek-v4-flash-cloud-t0.0__python3.py:

d = a - b
p = min(swapCost, 2 * flipCost)   # cost per opposite pair
candidates = {0, -a, b}
k0 = -d // 2
candidates.add(k0)
candidates.add(k0 + 1)
best = float('inf')
for k in candidates:
    if -a <= k <= b:
        a2 = a + k
        b2 = b - k
        cost = crossCost * abs(k) + p * min(a2, b2) + flipCost * abs(a2 - b2)
        if cost < best:
            best = cost
return best
