Problem Essence

A repunit is a number whose decimal representation consists entirely of 1s: 1, 11, 111, 1111, … . Given a positive integer k (2 ≤ k ≤ 105), find the smallest repunit that is divisible by k and return its number of digits.

If k has 2 or 5 as a factor, no repunit can ever be divisible by it — repunits are always odd and end in 1, so they are coprime to both 2 and 5 — and the answer is -1. For all other k, a solution always exists and can be found by tracking remainders modulo k as digits are appended, without ever building the large number itself.

Worked Example

Input: k = 3  ·  Expected output: 3

We want the smallest repunit divisible by 3. Instead of building 1, 11, 111, … as actual numbers, we maintain a running remainder under modulo 3. Appending a new digit 1 to a number with remainder r produces a new number equal to r × 10 + 1, so its remainder mod 3 is (r * 10 + 1) % 3.

StepOperationResult
Init rem = 0 Before any digit is appended
d = 1 (0 × 10 + 1) % 3 = 1 Repunit "1" ≡ 1 (mod 3) — not 0
d = 2 (1 × 10 + 1) % 3 = 2 Repunit "11" ≡ 2 (mod 3) — not 0
d = 3 (2 × 10 + 1) % 3 = 0 Repunit "111" ≡ 0 (mod 3) → return 3

Decision Rule / Algorithm

Precondition check: If k % 2 == 0 or k % 5 == 0, return -1 immediately. Every repunit is odd (last digit 1) and not divisible by 5, so no repunit can be divisible by a number that requires a factor of 2 or 5.

Main loop: Maintain rem = 0. For each digit count d from 1 to k: 

rem = (rem * 10 + 1) % k
if rem == 0: return d

If no d yields rem == 0 within k steps, return -1.

Why the loop bound of k is sufficient: The remainder values live in {0, 1, …, k−1}. By the pigeonhole principle, after k steps without hitting 0, some remainder must have appeared twice. Because the recurrence rem ↦ (rem·10+1) % k is deterministic, a repeated remainder means we are in a cycle that will never include 0 — so we can safely return -1. In practice, for all k coprime to 10, the answer always exists and is at most k.

Implementation Skeleton

# Python 3 — exact function signature from stats.json
class Solution:
    def minAllOneMultiple(self, k: int) -> int:
        # Repunits always end in 1: never divisible by 2 or 5
        if k % 2 == 0 or k % 5 == 0:
            return -1

        remainder = 0
        # Pigeonhole: at most k distinct remainders, so k steps suffice
        for digits in range(1, k + 1):
            remainder = (remainder * 10 + 1) % k
            if remainder == 0:
                return digits

        return -1   # unreachable for valid k coprime to 10

Reimplementation Checklist

  • Return -1 immediately if k % 2 == 0 or k % 5 == 0.
  • Initialize remainder = 0 (not 1) before the first iteration so the recurrence is uniform.
  • Apply the recurrence remainder = (remainder * 10 + 1) % k inside the loop — never build the actual repunit number.
  • Return the digit counter d as soon as remainder == 0.
  • Cap the loop at exactly k iterations; beyond k steps a cycle is guaranteed and no solution exists.
  • In Rust: cast k to i64 before arithmetic — intermediate rem * 10 + 1 stays below 106, safe for i32 too, but i64 is the safer habit.
  • In JavaScript/TypeScript: all arithmetic stays within safe integer range (k ≤ 105, max intermediate ≈ 106), so BigInt is not needed.
  • Verify edge case k = 1: the single repunit "1" has remainder 1 % 1 = 0, so the answer is 1. (Constraints say k ≥ 2, but good to confirm the loop handles it.)

Wrong But Tempting

① Build the repunit as a big integer directly

Generate n = 1, n = 11, n = 111, … and test n % k == 0 using Python's arbitrary-precision ints or Java's BigInteger. Each iteration the number grows by one digit, so n % k on a d-digit number costs O(d) big-integer work. Over k steps: O(k) × O(k) = O(k²) = 1010 ops for k = 105. TLE. The fix is to keep only the remainder — which costs O(1) per step.

② Iterate multiples of k, check if all digits are 1

For each multiple m = k, 2k, 3k, … convert to string and check all(c == '1' for c in str(m)). The smallest repunit divisible by k has up to k digits, so it can be as large as R(k) = (10k − 1) / 9. The number of multiples to check before reaching R(k) is R(k) / k ≈ 10k / (9k) — astronomically large even for k = 10. Completely intractable.

③ Forget the 2/5 guard and rely only on the loop

For k = 2: the remainder sequence is 1, 1, 1, … (period 1, never 0). A loop without a 2/5 check must run all k = 2 iterations and return -1 — happens to work because the loop bound is k. But for k = 10 the sequence is 1, 1, 1, … (period 1 again) and the loop still terminates correctly after k steps. However, omitting the guard loses an O(1) early-exit that has no downside: the guard is always cheaper than even one loop iteration. More importantly, skipping it is confusing to readers and causes a 6× runtime penalty in practice (see glm-5-cloud-t0.8-java at 50 ms vs 8 ms median).

Accepted Algorithm Families

Family A — Bounded for-loop with 2/5 guard (most common, ~25 files)

Check k % 2 == 0 || k % 5 == 0 first, then loop d = 1..k applying the recurrence. Return d on first zero remainder. The loop bound of k provides the implicit cycle guard. This is the canonical approach chosen by virtually every model. 

class Solution:
    def minAllOneMultiple(self, k: int) -> int:
        if k % 2 == 0 or k % 5 == 0:
            return -1
        remainder = 0
        for i in range(1, k + 1):
            remainder = (remainder * 10 + 1) % k
            if remainder == 0:
                return i
        return -1

Family B — While-loop until remainder == 0 (trust 2/5 guard)

After the 2/5 check, set rem = 1 % k and loop while rem != 0. Safe because for any k coprime to 10 the answer is guaranteed to exist, so the while-loop will always terminate. Has no explicit iteration cap — relies on the mathematical proof. 

class Solution {
    public int minAllOneMultiple(int k) {
        if (k % 2 == 0 || k % 5 == 0) return -1;
        int remainder = 1;
        int length = 1;
        while (remainder != 0) {
            remainder = (remainder * 10 + 1) % k;
            length++;
        }
        return length;
    }
}

Family C — Explicit cycle detection with visited array / set (~5 files)

Tracks seen remainder values in a boolean array or hash set. Returns -1 as soon as a remainder repeats. More defensive than Family A/B — does not rely on either the 2/5 shortcut or the loop-bound-equals-k argument, though it pays extra allocation cost. 

func minAllOneMultiple(k int) int {
    if k%2 == 0 || k%5 == 0 { return -1 }
    remainder := 1 % k
    length := 1
    visited := make([]bool, k)
    for remainder != 0 {
        if visited[remainder] { return -1 }
        visited[remainder] = true
        remainder = (remainder*10 + 1) % k
        length++
    }
    return length
}

Family D — No 2/5 guard, bounded for-loop (1 file)

Identical recurrence and loop bound, but omits the early 2/5 check. Correct because the loop bound of k still terminates properly (k steps of remainder 1,1,1,… for k=2 → returns -1). Observed to be slower in practice (50 ms vs 8 ms for Java peers). 

class Solution {
    public int minAllOneMultiple(int k) {
        int remainder = 0;
        for (int i = 1; i <= k; i++) {
            remainder = (remainder * 10 + 1) % k;
            if (remainder == 0) return i;
        }
        return -1;
    }
}
