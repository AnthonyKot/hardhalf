Problem Essence

You are given an integer array nums. A subarray is alternating if consecutive pairs strictly alternate between < and > -- equal adjacent elements are forbidden. You may remove at most one element from the original array, then pick any alternating contiguous subarray from the result. Return the maximum length of such a subarray.

The key difficulty is that removing one element can bridge two previously incompatible alternating segments if and only if the new adjacency (between the elements flanking the removed one) continues the alternating pattern of both sides. A length-1 subarray is always valid, so the answer is at least 1.

Worked Example

Input: nums = [2, 1, 3, 2]    Expected output: 4

Build two pairs of DP arrays (left-to-right and right-to-left), each tracking the longest alternating subarray ending/starting at each index, split by whether the last or first comparison step was "up" (prev < curr) or "down" (prev > curr).

Left-to-right pass -- left_up[i] and left_down[i]:

idx:       0    1    2    3
value:     2    1    3    2
           |    |    |    |
step dir:  --  down  up  down
left_up:   1    1    3    1
left_down: 1    2    1    4

Trace:

  • i=0: base case, both = 1.
  • i=1: 2 > 1 ("down") -- left_down[1] = left_up[0]+1 = 2, left_up[1] = 1.
  • i=2: 1 < 3 ("up") -- left_up[2] = left_down[1]+1 = 3, left_down[2] = 1.
  • i=3: 3 > 2 ("down") -- left_down[3] = left_up[2]+1 = 4, left_up[3] = 1.

No deletion is needed: max(left_up + left_down) = 4. The entire array 2 > 1 < 3 > 2 is already alternating. Answer: 4.

Decision Rule / Algorithm

Precondition: 2 <= n <= 1e5, values in [1, 1e5]. Equal adjacent elements break any alternating chain, so they must either be the deletion target or terminate the chain.

Step 1 -- left pass. Compute left_up[i] and left_down[i]: the length of the longest alternating subarray ending at i where the last comparison was "up" (<) or "down" (>) respectively. Base: all 1. Recurrence:

if nums[i-1] < nums[i]:   left_up[i]   = left_down[i-1] + 1
if nums[i-1] > nums[i]:   left_down[i] = left_up[i-1]   + 1
if nums[i-1] == nums[i]:  both reset to 1

Step 2 -- right pass. Compute right_up[i] and right_down[i] symmetrically, starting from the right. right_up[i] = length of alternating subarray starting at i where the first comparison is "up" (nums[i] < nums[i+1]).

Step 3 -- no-deletion answer. ans = max over all i of max(left_up[i], left_down[i]).

Step 4 -- try deleting each index r in [1, n-2]. The new adjacency is between nums[r-1] and nums[r+1]:

if nums[r-1] < nums[r+1]:  -- new bridge is "up"
    candidate = left_down[r-1] + right_down[r+1]
    # left must end "down" so the bridge reverses it;
    # right must start "down" for the same reason.

if nums[r-1] > nums[r+1]:  -- new bridge is "down"
    candidate = left_up[r-1] + right_up[r+1]

Why the bridge direction must match the opposite of each side's last/first step: if the left side ends "down" (prev > curr) and the bridge is "up" (curr < next), then the pattern at the junction is ...> <, which alternates correctly. The same argument applies symmetrically to the right side.

Complexity: O(n) time, O(n) space. The rolling O(1)-space variant (Family B below) folds both passes into one forward scan.

Implementation Skeleton

from typing import List

class Solution:
    def longestAlternating(self, nums: List[int]) -> int:
        n = len(nums)

        # --- left pass: alternating length ending at i ---
        left_up   = [1] * n   # last step was "up"   (nums[i-1] < nums[i])
        left_down = [1] * n   # last step was "down"  (nums[i-1] > nums[i])
        for i in range(1, n):
            if nums[i - 1] < nums[i]:
                left_up[i]   = left_down[i - 1] + 1
            elif nums[i - 1] > nums[i]:
                left_down[i] = left_up[i - 1]   + 1
            # else equal: both stay 1 (implicit from initialization)

        # --- right pass: alternating length starting at i ---
        right_up   = [1] * n   # first step is "up"   (nums[i] < nums[i+1])
        right_down = [1] * n   # first step is "down"  (nums[i] > nums[i+1])
        for i in range(n - 2, -1, -1):
            if nums[i] < nums[i + 1]:
                right_up[i]   = right_down[i + 1] + 1
            elif nums[i] > nums[i + 1]:
                right_down[i] = right_up[i + 1]   + 1

        # --- no-deletion answer ---
        ans = max(max(left_up), max(left_down))

        # --- try deleting each interior index ---
        for r in range(1, n - 1):
            if nums[r - 1] < nums[r + 1]:          # bridge is "up"
                ans = max(ans, left_down[r - 1] + right_down[r + 1])
            elif nums[r - 1] > nums[r + 1]:        # bridge is "down"
                ans = max(ans, left_up[r - 1]   + right_up[r + 1])
            # else equal neighbors -- no valid bridge, skip

        return ans

Reimplementation Checklist

  • Initialize all four DP arrays (left_up, left_down, right_up, right_down) to 1.
  • Left pass: extend left_up when nums[i-1] < nums[i]; extend left_down when >; reset both to 1 when equal (NOT just the inactive direction).
  • Right pass: mirror image -- extend right_up when nums[i] < nums[i+1]; extend right_down when >.
  • No-deletion answer: take max over the entire left_up and left_down arrays (right_ arrays give the same max, but left is sufficient).
  • Bridge merge loop runs from r=1 to r=n-2 (interior only -- endpoints have no opposite neighbor after deletion).
  • Bridge "up" (nums[r-1] < nums[r+1]) combines left_down[r-1] with right_down[r+1] -- not left_up with right_up.
  • Equal bridge (nums[r-1] == nums[r+1]) contributes nothing beyond the no-deletion answer; skip it explicitly.
  • Return ans; minimum possible answer is 1 (guaranteed by initialization and n >= 2).

Wrong But Tempting

1. Brute-force: try every deletion then every subarray

For each of the n deletion choices, scan all O(n^2) subarrays for alternation. Total: n * n^2 = n^3. At n = 1e5: 1e5 * 1e10 = 1e15 ops. Unacceptably slow by a factor of ~1e9.

2. Single sliding window without DP precomputation

Attempt to slide a window tracking "have I used my one skip?" at each failure point. This works for many simpler deletion problems but fails here because after skipping an element, the two flanking elements must form a valid bridge with the existing alternating prefix and suffix independently -- a single running state cannot capture both sides simultaneously. Wrong answers appear on inputs like [3,2,1,2,3,2,1] where the deletion is not at the first failure site.

3. O(n^2) -- for each right endpoint, binary-search or linear-scan for best left

Try all pairs (l, r) with at most one deletion inside. For each right endpoint, scanning left is O(n); total O(n^2). At n = 1e5: 1e10 ops, still ~1e4x too slow for a 2-second time limit. The required approach is O(n) via the DP precomputation.

Accepted Algorithm Families

Family 1 -- Bidirectional DP + Bridge Merge (O(n) time, O(n) space)

The dominant strategy across all languages. Precompute four O(n) arrays (left_up, left_down, right_up, right_down), then scan interior indices as deletion candidates. For each candidate r, check whether nums[r-1] and nums[r+1] form a valid bridge and merge the appropriate left/right values. Some variants add a prefix-max array and a suffix-max array to also capture the best alternating segment anywhere to the left/right of the deletion point, not just the one touching it.

Approx. 16 of 21 solutions. Languages: Python3 (5/6), JavaScript (3/4), TypeScript, Java (2/4), C++, Go (2/4), Rust.

var longestAlternating = function(nums) {
    const n = nums.length;
    if (n <= 1) return n;
    const up = new Array(n).fill(1);
    const down = new Array(n).fill(1);
    for (let i = 1; i < n; i++) {
        if (nums[i-1] < nums[i])       up[i]   = down[i-1] + 1;
        else if (nums[i-1] > nums[i])  down[i] = up[i-1]   + 1;
    }
    const rUp = new Array(n).fill(1);
    const rDown = new Array(n).fill(1);
    for (let i = n-2; i >= 0; i--) {
        if (nums[i] < nums[i+1])       rUp[i]   = rDown[i+1] + 1;
        else if (nums[i] > nums[i+1])  rDown[i] = rUp[i+1]   + 1;
    }
    let ans = 1;
    for (let i = 0; i < n; i++) ans = Math.max(ans, up[i], down[i]);
    for (let p = 1; p < n-1; p++) {
        if (nums[p-1] < nums[p+1]) ans = Math.max(ans, down[p-1] + rDown[p+1]);
        else if (nums[p-1] > nums[p+1]) ans = Math.max(ans, up[p-1] + rUp[p+1]);
    }
    return ans;
};
Family 2 -- Forward Rolling DP with Deletion Budget (O(n) time, O(1) space)

Instead of a right-to-left pass, maintain four rolling scalars: dp0_up, dp0_down (best ending here with 0 deletions, last step up/down), and dp1_up, dp1_down (same but with 1 deletion used). At each index i, the "delete i-1" case bridges dp0 from i-2 to i. This is O(1) space. Some solutions use an explicit 2D array dp[n][2] but the same DP recurrence.

Approx. 4-5 solutions: codex Java, kimi Go (rolling), minimax Go t1.0 (rolling), qwen3.5 Java (2D array variant).

Family 3 -- Bidirectional DP with Exhaustive Direction Enumeration

Same four DP arrays as Family 1, but instead of the two-branch bridge check, the merge loop explicitly iterates over all four combinations of (leftDir, rightDir) and tests compatibility with newDir (the direction of the bridge). This handles edge cases such as "full left + single right" or "single left + full right" more explicitly at the cost of code complexity.

2-3 solutions: deepseek-v4-flash Java, minimax Python (also checks partial combinations), minimax Go t0.0.

Wrong Answer 3 Three sub-patterns are plausible:
  • Bridge direction reversed: combining left_up[r-1] + right_up[r+1] when the bridge is "up" (nums[r-1] < nums[r+1]) -- the correct pairing is left_down + right_down. Every accepted Family-1 solution uses the opposite direction for each side.
  • Equal-neighbor bridge not skipped: when nums[r-1] == nums[r+1] there is no valid alternating bridge; failing to guard this generates a spurious candidate equal to left_len + right_len for an invalid join.
  • Endpoint deletion not handled: when r == 0 or r == n-1, the deletion removes an endpoint; the merge formula references out-of-bounds indices unless guarded. Accepted solutions restrict the bridge loop to r in [1, n-2].
