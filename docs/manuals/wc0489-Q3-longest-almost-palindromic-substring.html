Problem Essence

Given a string s, find the length of the longest substring that becomes a palindrome after removing exactly one character from it. Every palindrome of length 2 or more already qualifies because you can always remove one character and leave a palindrome. The task is to find substrings that are "one deletion away" from being a palindrome, and return the maximum length. With n <= 2500, an O(n^2) solution is the target complexity.

Worked Example

Input: s = "abca"   Expected: 4

We use the expand-around-center with one-skip strategy. Consider center at index 1 (character b), expanding as an odd-length palindrome:

The algorithm finds that the whole string "abca" (length 4) is almost-palindromic: after the core palindrome "b" is established, we try skipping the right-boundary mismatch character 'c' at index 2, then extend using matching pair s[0]='a' and s[3]='a'. Total length = 1 (core) + 1 (skipped char) + 2 (one pair) = 4. Removing 'c' from "abca" gives "aba", a palindrome.

Decision Rule / Algorithm

Core rule: A substring s[l..r] is almost-palindromic iff either (A) it is already a palindrome, or (B) there exists exactly one position whose removal produces a palindrome. At the first interior mismatch pair (i, j) after peeling equal outer pairs, the substring qualifies iff s[i+1..j] or s[i..j-1] is a palindrome.

Greedy expand-around-center strategy (matches official hints):

  1. Iterate every center (2n-1 centers: n odd + n-1 even).
  2. Expand outward while s[l] == s[r]. Let the matched core have length core.
  3. The core palindrome itself is already almost-palindromic (e.g., remove the middle char for odd length, or remove one of the adjacent center chars for even), so record core.
  4. If the expansion stopped at a boundary (one pointer ran off the string), you can include one more character and it is still almost-palindromic: record core + 1.
  5. If the expansion stopped at an interior mismatch (l, r):
    • Try skip-left: use s[l] as the deleted character, then continue expanding from (l-1, r). Count any additional pairs.
    • Try skip-right: use s[r] as the deleted character, then continue expanding from (l, r+1). Count any additional pairs.
    • Take the maximum.

Why the one-skip is sufficient: After the first interior mismatch, only one deletion can bridge it. Any further mismatch in the expanded region would require a second deletion, so the inner expansion loop after the skip is guaranteed to stop at the second mismatch (if any), and we take whatever length we have. This correctly enumerates all possible almost-palindromic substrings centered here in O(n) per center, giving O(n^2) total.

Alternative correct rule (DP): Let dp[i][j] = minimum deletions to make s[i..j] a palindrome. Then s[i..j] is almost-palindromic iff dp[i][j] <= 1. Recurrence: if s[i]==s[j] then dp[i][j] = dp[i+1][j-1]; else dp[i][j] = 1 + min(dp[i+1][j], dp[i][j-1]). This is O(n^2) time and O(n^2) space (or O(n) with rolling arrays).

Implementation Skeleton

class Solution:
    def almostPalindromic(self, s: str) -> int:
        n = len(s)
        best = 0

        def go(l: int, r: int) -> int:
            # Phase 1: expand matching pairs
            while l >= 0 and r < n and s[l] == s[r]:
                l -= 1
                r += 1
            core = r - l - 1  # palindrome core length
            result = core      # palindrome itself is almost-palindromic

            # Phase 2: try skipping one boundary character
            if l >= 0:          # skip s[l]
                result = max(result, core + 1)
                ll, rr = l - 1, r
                while ll >= 0 and rr < n and s[ll] == s[rr]:
                    ll -= 1
                    rr += 1
                result = max(result, core + 1 + 2 * ((l - 1) - ll))
            if r < n:          # skip s[r]
                result = max(result, core + 1)
                ll, rr = l, r + 1
                while ll >= 0 and rr < n and s[ll] == s[rr]:
                    ll -= 1
                    rr += 1
                result = max(result, core + 1 + 2 * (rr - (r + 1)))
            return result

        for i in range(n):
            best = max(best, go(i, i))      # odd-length center
            if i + 1 < n:
                best = max(best, go(i, i + 1))  # even-length center
        return best

The formula core + 1 + 2 * extra_pairs counts: the palindrome core, the skipped character, and the new symmetric pairs found after the skip. After the phase-2 loop, the number of new pairs matched when skipping left is (l-1) - ll and when skipping right is rr - (r+1).

Reimplementation Checklist

  • Handle both odd-length centers (l=i, r=i) and even-length centers (l=i, r=i+1); skip even when i+1 >= n.
  • Phase-1 expansion: advance l left and r right while characters match and bounds hold.
  • After phase 1, record core = r - l - 1 as a candidate answer (a palindrome qualifies).
  • If l >= 0 (stopped at interior mismatch or ran off right): try skip-left, re-expand from (l-1, r), count extra pairs as (l-1) - ll.
  • If r < n (stopped at interior mismatch or ran off left): try skip-right, re-expand from (l, r+1), count extra pairs as rr - (r+1).
  • Both conditions can be true simultaneously (mismatch case) -- run both branches and take the max.
  • Track the global maximum across all centers.
  • Edge: a single character has core=1 and either boundary can give core+1=2; every length-2 substring is almost-palindromic (remove one char -> 1-char palindrome).

Wrong But Tempting

Approach 1: Brute-force O(n^3) check

For each substring s[i..j], try removing each character k in [i,j] and check if the remaining string is a palindrome.

Complexity: O(n^2) substrings * O(n) removals * O(n) palindrome check = O(n^4). With n=2500: 2500^4 / something... even O(n^3) = 2500^3 = 15.6e9 ops, far over the ~10^8 limit. Even with hashing to make each check O(1), O(n^3) = 15.6e9 is TLE.

Approach 2: Expand-around-center but only try skip once (boundary only)

Only add +1 when one pointer runs off the edge of the string, missing interior mismatches where skipping either side and continuing expansion would yield a longer result.

This gives wrong answers: for "zzabba", without re-expanding after the skip, the algorithm would not find that skipping 'z' at position 1 and then finding "abba" gives length 5. Interior skip + continuation is essential.

Approach 3: DP where dp[i][j] stores the full deletion set

Storing which characters to delete (not just the minimum count) to check exact-1-deletion. Memory: O(n^2) entries each holding a set -> O(n^3) total. With n=2500: 2500^2 * 2500 = 15.6e9 bytes. Completely infeasible. The minimum-count scalar dp[i][j] is all that is needed; checking dp[i][j] <= 1 is sufficient.

Accepted Algorithm Families

Family A -- Expand-Around-Center with One Skip (Greedy)

For each center (odd and even), expand while s[l]==s[r], then on the first mismatch try skipping left or skipping right and continue expanding. O(n^2) time, O(1) space. This is the approach described in the official hints.

// interior mismatch: try skipping left or right
if (left >= 0 && right < n && s[left] !== s[right]) {
    // skip left
    let l1 = left - 1, r1 = right, len1 = len + 1;
    while (l1 >= 0 && r1 < n && s[l1] === s[r1]) {
        len1 += 2; l1--; r1++;
    }
    curMax = Math.max(curMax, len1);
    // skip right
    let l2 = left, r2 = right + 1, len2 = len + 1;
    while (l2 >= 0 && r2 < n && s[l2] === s[r2]) {
        len2 += 2; l2--; r2++;
    }
    curMax = Math.max(curMax, len2);
}

Family B -- DP: Minimum Deletions to Palindrome

dp[i][j] = minimum characters to delete to make s[i..j] a palindrome. Answer: longest [i,j] where dp[i][j] <= 1. Rolling-array variants reduce space to O(n). O(n^2) time.

for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        if (s.charAt(i) == s.charAt(j)) {
            dp[i][j] = (i + 1 <= j - 1) ? dp[i + 1][j - 1] : 0;
        } else {
            dp[i][j] = 1 + Math.min(dp[i + 1][j], dp[i][j - 1]);
        }
    }
}

Family C -- Boolean PAL Table + Boolean ALMOST Table

Precompute pal[i][j] (is palindrome), then derive almost[i][j] using: if s[i]==s[j] then almost[i][j] = almost[i+1][j-1]; else almost[i][j] = pal[i+1][j] || pal[i][j-1]. O(n^2) time, O(n^2) space.

Family D -- PAL Precompute + LCP / next-mismatch / Manacher

Build the palindrome table, then use more advanced structures: LCP of s vs rev(s) to identify the first mismatch depth and directly compute the matching prefix; or precompute next_mismatch[i][j]; or run Manacher's algorithm on each (n-1)-length string formed by removing one character. O(n^2) time, O(n^2) space (Manacher's variant is O(n^2) time, O(n) space per call).

Time Limit Exceeded 10 O(n^3) or O(n^4) algorithms -- e.g., brute-force substring enumeration combined with O(n) per-removal palindrome check, or O(n^2) DP with a naive O(n) inner check. Wrong Answer 2 Likely incomplete handling of the "exactly one deletion" constraint -- either counting palindromes (zero deletions) as invalid, or allowing substrings of length 1 as the answer (a single character cannot become a palindrome after removal since that leaves an empty string, depending on the judge).
